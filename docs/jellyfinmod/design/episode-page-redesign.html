Episode page, built from your four points

One design in five steps. Every step is additive to the stock page and keeps every control a D-pad stop. Two steps touch stock containers; both were approved on 7 Oct and are recorded as Principle 0 exceptions.

1 · Get a release, next to Favorite

One icon button joins upstream's header row, between Played and Favorite. It opens the release picker. With no file it is the only way in; with a file it searches for another quality.

The new button is a stock button-flat detailButton with a detailButton-icon: same 1.6em icon, same padding, same flat hover, tooltip "Get a release". Nothing about it is mod-styled.

How it is built

A DOM insert into .mainDetailButtons before .btnUserRating, the same technique as the versions mount. The row is a focuscontainer-x, so the D-pad reaches it without new rules. Administrators only, since the picker is admin-only today.

Decisions

Decided 7 Oct: icon cloud_download.

Principle 0. This is the first mod control inside a stock container. It needs a parity check on every upstream merge.

2 · The Video row becomes the file chooser

With two or more files, the Video value gains a chevron. Clicking it slides a list down in the format you drew: mark, resolution, pretty-printed quality, Default chip, then the row's own icons. Picking a row selects that file and the list slides back. Get another quality is the last row of the list. One file: the row stays as it is today, and the icons sit at the end of it.

Round, icon-only row actions at least 2.5em across: grey, the cross red, the pin blue while kept; each its own stop on TV (user, 8 Oct). Pin and cross are administrator-only; history shows to everyone.

How it is built

The chooser is a mod component that drives the stock .selectSource through its own change event, exactly as the current rows do, so Play, audio and subtitles follow. The slide uses a height transition on the list, with prefers-reduced-motion honoured.

Pin calls the existing per-file Keep; cross calls Remove this version with its stock confirmation. Both exist today as buttons, so this is a re-homing, not new behaviour.

Decisions

Decided 7 Oct: hide the stock Version select while the chooser is mounted. With two files upstream shows its own Version select above Video; the chooser does that job. Upstream's select stays in the DOM and keeps working, it is only not shown, and it reappears if the chooser fails to mount. Recorded as a Principle 0 exception of the §7.3 kind.

Video streams. Upstream's Video row is really a video-stream select. Files with one stream (nearly all) render as text, which is what the chooser replaces. A file with two video streams keeps upstream's select under the chooser.

3 · History per file, in a popup

The first icon on a row opens a small popup with that file's events only: grabbed, imported, kept, stopped keeping, removed. Short dates, no file name, since the row already is the file.

A MUI popover, so it obeys the remote by §13 rule 9: Back closes it and focus returns to the history icon.

How it is built

The popup filters the entry's history to one file. Today's HistoryRecord carries an episode id but no file id, so the plugin gains a bindingId on events that concern one file (keep, unkeep, import, remove, grab once bound). Events older than that change have no file and show under a one-line "earlier" group on the episode, not in any file popup.

Decisions

Decided 7 Oct: drop episode-level events from the episode page. Monitoring changes, catalog adds and window changes belong to no file; they stay out of the popups, the old History line goes, and they remain on the series page.

4 · The Played tick wears a countdown badge

Once the episode is watched and a removal is scheduled, the stock Played tick keeps its size and gains a small badge at its bottom-right corner: days until the file goes. No warning box, no sentence.

Variants of the tick

Stock already turns the tick red once played. The icon keeps its size; the mod adds a small badge at the icon's bottom-right corner, a bare bold number, no fill, sitting over the tick's lower-right arm with a soft dark halo so it reads against the red: the number of days ("5", "0" on the day, "!" when overdue), accent blue "∞" when kept. Tooltip: "Played · removed on 12 Oct unless kept (marked played)". Everyone sees the badge, matching the current rule that every viewer sees the date.

How it is built

The badge is a small span inserted inside the stock Played button, as the second child of its .detailButton-content, positioned over the icon's lower-right arm as bare bold text with a soft text-shadow in the page background colour, no pill, so it reads over the red tick without covering it. The icon is not touched and keeps its 1.6em size, so the button is exactly as wide and tall as its neighbours. The badge is inside the button's hit area and focus ring. The button itself stays upstream's: its element only ever touches the icon's classes and the title, so the span survives every played toggle. The stock click still toggles played. The number is computed from the absolute deadline the plugin already returns, never cached as a count. If upstream ever changes the button's markup the insert fails quietly and the page shows the stock tick alone.

No mod-generated Played or Favorite button is needed. Replacing a stock button would break Principle 0 and would have to re-implement its played logic; inserting one span into it does not.

Decisions

Decided 7 Oct: Keep stays on the pin only. The countdown is not clickable; the stock tick keeps its stock click. The old warning box's Keep goes with the box.

Several files with different dates. The number shows the nearest date. The chooser rows show each file's own date in the quality text, as in your sketch ("removes 12 Oct").

5 · No file: the track block becomes Get a release

When the episode or movie has no file, there is no Video, Audio or Subtitles to show. The whole block is replaced by one control in the same place: a raised Get a release button, with the header icon from step 1 still present above it. Nothing else fills the gap.

How it is built

A file-less episode has no Jellyfin item, so it is served by the mod's own file-less page, which already mirrors the stock layout. That page drops its current button row and renders the raised button where .trackSelections would be: a stock emby-button raised button-submit with the same cloud_download icon. After a grab the button gives way to the existing queue status line until the file lands.

Notes

Non-administrators see neither the header icon nor the raised button, since release search is admin-only; they see the overview and, during a download, the status line. The series page keeps its per-episode rows as they are.

Decided 7 Oct 2026

  • Hide the stock Version select while the chooser is mounted.
  • Header icon: cloud_download, in stock detail-button style.
  • Keep lives on the pin only; the countdown is read-only.
  • Episode-level history events are dropped from the episode page.
