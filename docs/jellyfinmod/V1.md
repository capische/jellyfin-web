## Why

The runtime host is Jellyfin 12.0.0. It groups several files of a movie, and now of an episode, as versions of one
main item; it hides extra versions from ordinary queries; it groups `S01E01-E02` with `S01E01`, because its episode
key ignores the ending number; and it marks every version played, without a date, when one is finished. The retarget
(`p7.s5`) already binds a movie's local file versions through `GetLocalAlternateVersionIds`. Everything else about
versions is still blocked or missing: merged (linked) versions, every episode version, identity checks, absence decided
by the file, safe single-version delete, and a device-appropriate default copy.

**V1 is the single owner of version behaviour** (user, 2026-09-25). Phase 6 M5–M8, Phase 10 per-version retention
(E7) and the future Phase 12 route through it.

## The user's decisions (2026-09-24), binding

1. **Other copies expire together.** If any version of a title or episode is watched after the retention baseline,
   all its versions become eligible together; a per-file Keep still protects a chosen copy (retention decision 6).
2. **Double-episode files** (`S01E01-E02` grouped as a version of E01; E02 gets no item): each file's own episode
   range decides; the file is deleted only when every episode in its range is watched and past its window. E02's only
   copy is never deleted because E01 was watched.
3. **Safe version delete.** Admins get **Remove this version**: exactly one media file, through the plugin's exact
   unlink. The folder, sidecars (subtitles, artwork, `.nfo`) and other versions stay; the title stays in the library.
   Removing the **last** version also keeps the folder and sidecars, and the title stays in the catalog as not
   downloaded. Stock *Delete media* gets an additive warning in the new interface whenever a title has more than one
   file. "Folder should stay, so it's a part of media library."
4. **Pick the copy per device.** The new interface preselects the copy that suits the device (4K + Dolby Vision on
   the LG webOS TV, 1080p on a phone); the user can still switch. V1 builds the mechanism and a sensible default
   mapping; full device presets are Phase 12 (M10–M21).

## Boundaries

**Left to Jellyfin** (analysis §6): grouping and main-version choice, version names and order, playback (per-user
default, `MediaSourceId`, resume per version), marking every version played, *Group versions* / *Split versions*
as admin tools. V1 never calls `MergeVersions` and never renames an existing file.

**JellyfinMod owns, in V1:** listing every version of a movie or episode through `primary.GetMediaSources(false)`;
identity and episode-range checks per version; absence decided by the file; rebinding when the main version changes;
watched evidence, holdings and retention across all versions; per-version remove; the stock-Delete warning; the
device preselect.

## Proposed defaults — not user-approved unless marked

**Answered by the user, 2026-09-28** (through the coordinator's question tool), on the four defaults this plan
proposed:

1. **Remove this version:** "Only per-file Keep blocks". Works with retention off; title Keep and seeding do not block
   it (the seeding copy is a separate hardlink); a per-file Keep refuses it. As proposed.
2. **Last version removed:** "'Not downloaded', stop monitoring". Removing the last copy returns the title (or episode)
   to *Not downloaded* **and unmonitors it**, so automation does not grab it again; the folder and sidecars stay. The
   confirmation says so before anything happens ("This removes the last copy and stops monitoring"). This replaces
   the proposal of leaving monitoring unchanged.
3. **Device preselect:** "TV best, phone ≤1080p". TV the highest Dolby Vision / HDR copy, mobile the best copy at or
   below 1080p (SDR preferred), desktop Jellyfin's default; the user can always pick another. As proposed.
4. **Episode upgrades:** "On by default". `episodeUpgradesEnabled` defaults to **on**. This replaces the proposal of
   keeping it off. **Existing installs:** the V1 migration sets the stored value to on as well, not only the default for
   unset values: until V1 the switch was a safety block waiting for episode versions to be tracked (PHASE6 decision 5),
   nobody chose it, and the user expects episodes to upgrade. An administrator can still turn it off.
   What it means with V1: an episode upgrade imports `Series SxxEyy - Label` into the episode's own season folder, which
   Jellyfin 12 groups with the held file (same folder, same season and first episode), V1 binds it as a version and the
   older file is replaced at once (PHASE10 Q10) through the executor with every physical protection. Multi-episode
   files are never replaced (unchanged), and an episode whose held copy is a multi-episode file is not upgraded at all
   (`multi_episode_held`): a single-episode upgrade would group under E01 while E02 still needs the double file, so the
   replacement could never happen and the grab would be wasted. A grab whose import would not group (the held file does
   not parse to the same season and episode) is blocked before linking (`versions_not_grouped`, S2).

| Decision | V1 default |
| --- | --- |
| Identity of a version group | Every version must agree with the title on: media type, the target library (it must be inside the title's library), TMDB / IMDb / TVDB id wherever both carry one, and for episodes the series and the season plus **first** episode number. Any disagreement refuses the whole group, `version_identity_conflict`: bindings and state stay as they were, retention blocks the title, the reconciliation summary names it. A differing **last** episode number is not a conflict: it is a multi-episode version (decision 2). |
| Multi-part (stacked) version | Bound per version, never a whole-title failure; retention and Remove refuse it, `multi_part_unsupported` (C17). |
| Present but not reported | A bound file that Jellyfin stops listing keeps its binding while the file is on disk; absence is recorded only when the file is provably gone or another file replaced it (C5). Retention blocks such a target, `versions_unverified`. |
| Remove this version (**answered 1**) | Admin only; allowed with retention off (an explicit act, like stock Delete). Title Keep and seeding do not block it (only the library link goes; a seeding copy keeps its own link, and History says 0 bytes freed while it exists). Refused: a per-file Keep on that file (`version_kept`, un-keep first), the file playing (`active_session`), multi-part, unwritable media, changed storage or identity. A multi-episode file may be removed; the confirmation names every episode it holds. |
| Last version removed (**answered 2**) | Entry or episode becomes `none` ("Not downloaded"), not `reclaimed`, and is **unmonitored** (for a series: that episode); the confirmation says so. No `media_missing`. |
| Device preselect (**answered 3**) | TV layout: highest resolution, Dolby Vision, then HDR, preferred at equal resolution. Mobile layout: the highest resolution at or below 1080p, SDR preferred. Desktop: Jellyfin's own default (unchanged). Never overrides a version the user is part-way through, or a choice made on the page. Applies on the detail page, where the stock select decides what Play sends; cards' Play buttons keep Jellyfin's default. |
| `episodeUpgradesEnabled` (**answered 4**) | **On by default**, and the migration turns the stored value on (see answer 4). Episode upgrades replace immediately; multi-episode holdings are not upgraded (`multi_episode_held`). |
| Stock Delete warning | Shown inside the stock confirmation dialog (injected by the mod, no upstream patch) and as a line in the mod's version section, worded per case: a movie in its own folder (whole folder, every version, sidecars and extras) or an episode or shared-folder movie (the selected file and every file whose name starts with it). |

### S1 — version enumeration and identity (C3, C4, C13, C17, C2)

- `NativeVersionSet` (new, plugin): for a main item, `GetMediaSources(false)`; each source id resolved with
  `GetItemById`; per version its item id, path, stacked flag, provider ids, library membership and, for episodes, its
  own season, first and last episode number. The main item is `PrimaryVersionId` when set and readable, else the item.
- Movies: `JellyfinNativeTitleSource.Snapshot` binds every version (local and linked) as a representation owned by the
  navigable main item; the `PresentationUniqueKey` group check is replaced by the identity rule. A linked version from
  another folder of the same library and TMDB id is a version; any disagreement refuses the title
  (`version_identity_conflict`, observation conflict: nothing changes).
- Episodes: `GetEpisodes` adds, for each main episode, its extra versions as observations owned by that episode. A
  version with a longer range (`S01E01-E02` under `S01E01`) binds to its first episode and covers the later numbers
  exactly like a multi-episode main file does today (RET2-R7). A version whose first number differs refuses the
  episode group.
- Migration `V1Versions` (forward-only, in place from 0.1.0.0): `EpisodeBindings.OwnerItemId` (nullable) so an
  episode's navigable item stays the main; `UpgradeOperations.SupersededPath` (for S2).
- `GET /Entries?jellyfinItemId=<extra version>` resolves an extra version to its main before lookup (C13).
- Health capability `versions.v1`.

**Acceptance:** suites pass; the migration applies to a copy of the 28096 database with integrity and foreign-key
checks clean and every table's row count preserved. Live in S7.

### S2 — absence, rebinding, upgrades, import grouping (C5, C6, C14)

- Absence confirmation removes a binding only when its file is provably gone or replaced at its path; present but
  unreported keeps it and names the title in the summary. The per-title stale-source removal follows the same rule.
- When the main version changes, the old main's binding follows it as an extra version with its clock untouched;
  only the arriving file is new (RET2-R1 unchanged).
- M5: the superseded version is found by binding, else by `SupersededPath`; `superseded_missing` only when that file
  is provably gone; a present but unbound superseded file waits (`superseded_untracked`).
- Import beside an existing file: before linking a second movie version, every video in the folder must satisfy
  Jellyfin 12's grouping rule for that folder name (`VideoListResolver`); otherwise the import blocks
  `versions_not_grouped` and nothing is linked. Episode versions: the existing file must parse to the same season
  and first episode.
- Episode upgrades on by default (answer 4): `episodeUpgradesEnabled` defaults to on and the V1 migration sets the
  stored value on; an episode whose held copy is a multi-episode file is not upgraded (`multi_episode_held`).

**Acceptance:** suites pass (Phase 2 absence, Phase 5, Phase 6 upgrade scenarios); live in S7.

### S3 — retention over every version (C1, C7, C9, C10, E7, RET4-R2, P3-A–E)

- The guard compares what Jellyfin plays (the main item's media sources) with what the plugin binds, by path, for
  movies **and** episodes. It blocks only when a played file is untracked (`versions_untracked`,
  `episode_versions_untracked`), when the group fails identity (`version_identity_conflict`) or a bound file is no
  longer one of Jellyfin's versions (`versions_unverified`). Where V1 tracks every file, the blocks lift: this is
  PHASE10 **E7**, built on V1.
- Decision 1: one completion per movie or episode across every bound version (already so); a propagated played flag
  without a date is never a watch.
- Decision 2: a version whose own range covers several episodes follows the multi-episode rule over its own range.
- M7 ordering (lowest resolution first) applies to episode versions too.
- RET4-R2 remainder: a file that Jellyfin plays as a linked version of any other main item (found through
  `GetItemIdsWithAlternateVersions` over the library, not only through tracked items) blocks the target unless that
  main item is the same tracked title.
- P3-A–E from PHASE10: listener `TryAdd`/`TryUpdate` loop; the repair task logs write failures at Warning with a
  skipped count; the evaluator warns on an unreadable item; one deferred retry after a passing read failure; `p22-stale`
  behind an explicit flag.

**Acceptance:** suites pass (Phase 3 protection, Phase 10); live in S7.

### S4 — Remove this version and the version read model (decision 3, C11, C12)

- `POST /JellyfinMod/Entries/{id}/Versions/{bindingId}/Remove` (admin; 401 anonymous, 403 ordinary user): a Phase 3
  `RetentionOperation` with provenance `version_removed` through the executor's exact unlink (`UnlinkPinned`) and
  native cleanup with file deletion off, under the same locks; History `version_removed` with bytes unlinked and
  released. Refusals as in the defaults table, each a 409 with its reason. Removing the last file of a movie or episode
  leaves it *Not downloaded* and unmonitored (answer 2), with History saying so.
- `VersionDto` gains `tracked`, `removable`, `inProgress` (the requesting user is part-way through it) and
  `episodeRange`, and `isLast` (removing it stops monitoring). Rows are built from Jellyfin's media sources joined with bindings, so an untracked source shows as a
  row; `isDefault` is Jellyfin's first source for the main item. `VersionQuality.HeldAsync` reads holdings from all
  media sources (C12).
- Health capability `versions.remove`.

**Acceptance:** suites pass; HTTP matrix in S7.

   both bindings present, the old one now an extra version, no binding lost, no `media_missing`, no silent reset.
4. **Two-file episode:** `S01E01` 1080p + 720p in one folder: two episode bindings, one episode, version rows show both.
5. **`S01E01` + `S01E01-E02` in one folder:** the double file binds to E01 with range E01–E02; E02's row points at it;

   file and E02 stay byte-identical (`multi_episode_not_all_due`); after the double file itself is watched and past
   its window it goes.
6. **Two different episodes grouped** (`S01E03` merged with `S01E04` through *Group versions*): refused

8. **Absence by the file:** a bound file hidden from Jellyfin but on disk (library monitor off, item deleted without

## Implementation notes — 2026-09-28

- **How versions are read.** `NativeVersions` (plugin) assembles exactly the list `GetMediaSources(false)` builds in
  v12.0 (`Video.GetAllItemsForMediaSources`): the main item, `ILibraryManager.GetLinkedAlternateVersions` and each
  one's `GetLocalAlternateVersionIds`. It uses those members rather than calling `GetMediaSources` itself, which would
  read media streams, attachments and segments for every source on every observation. The live checklist compares the
  plugin's list with Jellyfin's `PlaybackInfo` media sources (row 1).
- **Stacked files** are no longer a whole-title failure: each stacked version is bound and retention and Remove refuse
  it on its own (`multi_part_unsupported`).
- **P3-A, P3-B, P3-C, P3-E are done; P3-D is not.** A one-minute deferred retry in the listener changed the event order
  the Phase 3 suite depends on ("All users did not wait for the last accessible completion"); the gap it would close
  only delays evidence until the next event or the nightly repair, so it stays recorded in PHASE10 as open.
- **Suites.** Three suite fixtures were brought to Jellyfin 12's model rather than relaxed: Phase 2 records a merge on
  the main item (`LinkedAlternateVersions`, `GetLinkedAlternateVersions`), Phase 6 reads the settings revision the V1
  migration moved and expects episode upgrades on, and one Phase 3 protection case accepts `versions_unverified` where
  its main item does not list the merged copy (a real main item does, which gives `versions_untracked`).

## Risks

| Risk | Response |
| --- | --- |
| Following a wrong group deletes another title's file | Identity check per version; any disagreement refuses the group; merged versions only within one library and TMDB id |
| Double-episode file deleted because E01 was watched | Per-file range; the multi-episode rule reads the file's own played date; a propagated flag has no date |
| Enumeration cost on large libraries | `GetMediaSources` only for items that have versions (`LocalAlternateVersions`, or `GetItemIdsWithAlternateVersions` in one query per page) |
| Remove this version removes more than one file | Exact `UnlinkPinned` of one inode path; native cleanup with file deletion off; SHA-256 of folder contents before and after in the live row |
| Main-version promotion changes the title's item id | Entries point at the navigable main recomputed on every observation; lookups by any version id resolve to the main |
