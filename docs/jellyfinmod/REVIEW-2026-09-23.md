## S4-R1 — Recovery stops after a second failed load

- **Status:** open. **Priority:** P1.
- **Location:** plugin repository, `JellyfinMod/Services/Web/WebDocumentRenderer.cs:108–125`.
- **Trigger:** a patched `/web` document cannot load the mod bundle, falls back to stock,
  then the user reloads or revisits `/web` in the same tab while the bundle remains unavailable.
- **Cause:** fallback sets `jfmod-stock-fallback` in session storage. Only successful mod
  loading clears it. The next failed load returns before requesting the stock document.
- **Impact:** the recovery path can leave the login page and Dashboard inaccessible in that
  tab, despite a usable stock copy being present.
- **Fix direction:** scope recursion prevention to the recovery attempt, or clear the latch
  after successful recovery without introducing a fallback loop.
- **Acceptance:** make bundle assets unavailable on an isolated host with takeover active.
  Verify stock login/Home and Dashboard remain usable on the first visit, reload and repeat
  visit in the same tab. Also verify an unavailable stock copy cannot cause a reload loop.

## S4-R2 — Takeover ignores the server base URL

- **Status:** open. **Priority:** P2.
- **Location:** plugin repository, `JellyfinMod/Services/Web/WebRootTakeover.cs:231–232`.
- **Trigger:** Jellyfin is published under a prefix such as `/jellyfin`.
- **Cause:** the patched document roots assets at `/web-mod/<bundleId>/`, omitting the prefix.
  `Api/WebController.cs` already includes `Request.PathBase` for its own document responses,
  but takeover renders outside that request path.
- **Impact:** scripts and styles request the wrong address, preventing the mod interface from
  loading under the configured prefix.
- **Fix direction:** include the host's configured base URL when rendering the takeover
  document, as specified in Phase 7's delivery contract.
- **Acceptance:** run takeover on an isolated host under a nonempty base URL and verify the
  normal `/jellyfin/web/` entry loads the mod, including lazy chunks and navigation. Verify
  stock recovery there and retain the existing empty-base-URL behavior.

## S4-R3 — First takeover can lose its recovery record

- **Status:** open. **Priority:** P2.
- **Location:** plugin repository, `JellyfinMod/Services/Web/WebRootTakeover.cs:233–246`;
  also inspect the missing-record branches in `Reconcile` and `Restore`.
- **Trigger:** the process stops, or the state-file write fails, after the first replacement
  of `index.html` but before `WriteState(updated)` completes.
- **Cause:** the live document is replaced before its durable recovery record is saved.
- **Impact:** on restart, the engine finds a marked document without a record and refuses
  reconciliation and restoration, even though the pristine and stock copies were written.
  Manual recovery is required.
- **Fix direction:** make recovery metadata durable before replacing the live document, or
  introduce a recoverable transaction state; preserve checksum verification and safe refusal
  of genuinely unknown files.
- **Acceptance:** interrupt a first takeover at this boundary on a disposable host with real
  filesystem state, then restart. Verify it reconciles safely and disabling takeover restores
  the original document byte for byte. Cover state-write failure as well as interruption.
